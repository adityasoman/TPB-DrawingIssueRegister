## Project Overview

TPB-DrawingIssueRegister is an Excel task-pane add-in built on the Office.js API. The repo currently holds the unmodified `office-addin-taskpane` scaffold generated by `yo office`/Yeoman (`package.json` name is still `office-addin-taskpane`, `manifest.xml` provider is still `Contoso`) — no drawing-issue-register-specific logic has been added yet.

All project files live in the nested `TPB-DrawingIssueRegister/` subfolder (repo root only has `.gitignore` and this file), so `cd TPB-DrawingIssueRegister` before running any command below.

## Tech Stack

| Technology | Purpose |
|------------|---------|
| Office.js (`@types/office-js`, `@types/office-runtime`) | Excel task-pane API |
| TypeScript | All source in `src/` |
| webpack 5 + babel | Bundling (`babel-loader`, `@babel/preset-typescript`) |
| office-addin-debugging / office-addin-dev-certs | Local sideload + HTTPS dev certs |
| office-addin-lint / office-addin-prettier-config | Linting and formatting |

## Commands

Run from `TPB-DrawingIssueRegister/`:

```bash
npm install           # install dependencies
npm start              # office-addin-debugging start manifest.xml — sideloads into Excel desktop and starts dev server
npm stop                # office-addin-debugging stop manifest.xml
npm run dev-server      # webpack serve --mode development (dev server only, no sideload)
npm run build            # webpack --mode production
npm run build:dev        # webpack --mode development
npm run watch             # webpack --mode development --watch
npm run lint / lint:fix    # office-addin-lint check / fix
npm run validate            # office-addin-manifest validate manifest.xml
npm run signin / signout     # office-addin-dev-settings m365-account login/logout
```

There is no test runner configured — no test files, no `test` script.

## Architecture

```
TPB-DrawingIssueRegister/
├── manifest.xml              # Add-in manifest: IDs, permissions, ribbon button, taskpane/commands URLs
├── webpack.config.js         # Entry points: taskpane, commands; dev-server HTTPS via office-addin-dev-certs
├── src/
│   ├── taskpane/
│   │   ├── taskpane.html      # Task pane markup (loaded at manifest's Taskpane.Url)
│   │   ├── taskpane.ts         # Entry point, just imports ./excel
│   │   ├── excel.ts             # Office.onReady + runExcel(): all Excel.run interaction logic goes here
│   │   └── taskpane.css
│   └── commands/
│       ├── commands.html       # Function-file page for ribbon commands (loaded at manifest's Commands.Url)
│       ├── commands.ts           # Entry point, imports ./commands.excel
│       └── commands.excel.ts      # Ribbon button actions, registered via Office.actions.associate
└── assets/                    # Add-in icons (16/32/64/80/128 px) + logo, referenced by manifest.xml
```

Two independent entry points are bundled by webpack: `taskpane` (the pane UI shown via the ribbon button) and `commands` (headless function file for ribbon actions that don't open the pane, e.g. `setRangeColorInExcel` in `commands.excel.ts`). Both currently only demonstrate `Excel.run` by filling the selected range yellow — that's the sample behavior to replace with real drawing-issue-register logic.

All `Excel.run` calls follow the standard Office.js pattern: `context.workbook...` → `.load(...)` on anything you need to read → `await context.sync()` → read loaded properties. Wrap in try/catch and log errors to console (per the existing sample) until real UI error handling is added.

## Local development

`npm start` requires Excel desktop installed and uses `office-addin-dev-certs` to trust a local HTTPS cert for `localhost:3000` — the manifest's `SourceLocation`/`Commands.Url` point there. If sideloading fails, check that the dev cert is trusted (`npx office-addin-dev-certs install`) and that no other process holds port 3000.
